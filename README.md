# 연금 ETF 리밸런서

NH투자증권 **Namuh PLUG OpenAPI**(https://www.nhplug.com) 의 실시간 시세로 연금저축/IRP ETF 포트폴리오를
**정적 리밸런싱**(고정 목표비중, 주기적 조정)하는 로컬 웹앱입니다.

- **신규 투입 계산** — 투입금액을 입력하면 목표비중에 따라 종목별 매수 수량을 계산
- **리밸런싱 팝업** — 접속할 때마다 실시간 시세로 현재비중을 계산해, 목표비중에 맞추기 위한 **매도 → 매수 수량**을 팝업으로 제시
- **거래 반영** — 팝업에서 "거래 완료"를 누르면 보유수량·예수금·리밸런싱 일자가 갱신되고 기록이 남음
- **계좌 잔고 불러오기** — NH투자증권 계좌의 실제 보유수량/예수금을 가져와 반영 (선택)
- **ETF 검색** — NH Plug 종목마스터(`m_new_stock.mst`)로 ETF 1,100여 종목 이름/코드 검색
- **캘린더 알림(.ics)** — 앱은 푸시 알림을 보낼 수 없으므로, 매월 반복 일정으로 캘린더에 등록

## 빠른 시작

```bash
npm install
cp .env.example .env      # NHPLUG_APP_KEY / NHPLUG_APP_SECRET 입력
npm start                 # http://127.0.0.1:3000
```

API 키가 없어도 실행됩니다. 이때는 **모의 시세**(종목마스터의 전일종가)로 동작하며 화면 상단에 표시됩니다.
키를 넣으면 NH Plug 실시간 시세로 자동 전환됩니다.

### API 키 발급
1. https://www.nhplug.com → API 사용신청 (NH투자증권 계좌 필요)
2. 발급된 AppKey / AppSecretKey 를 `.env` 에 입력
3. 접근토큰은 자동 발급·캐시(`data/token.json`, 24시간)되며 만료/401 시에만 재발급합니다.

## 사용 흐름

1. **포트폴리오 설정** 탭 — ETF 검색으로 종목 추가, 목표비중(%) 입력(합계 ≤ 100, 나머지는 현금), 보유수량/예수금 입력 → 저장
   - 이미 계좌에 보유 중이라면 "계좌 목록 조회 → 잔고 불러오기 → 반영" 으로 수량/예수금을 가져올 수 있습니다.
2. **신규 투입 계산** 탭 — 첫 매수 또는 추가 납입 시 투입금액 입력 → 종목별 매수 수량 확인 → 체결 후 "보유수량에 반영"
3. **리밸런싱** 탭(기본) — 접속 시 자동 팝업. 매도 수량 → 매수 수량 순서로 실행한 뒤 "거래 완료 → 보유수량·예수금 반영"
   - 팝업의 "추가 투입금액"에 이번 달 납입액을 넣으면 납입 + 리밸런싱을 한 번에 계산합니다.

### 리밸런싱 규칙 (설정 탭)
| 항목 | 의미 | 기본값 |
|---|---|---|
| 리밸런싱 밴드 (%p) | 현재비중과 목표비중 차이가 이 값보다 작으면 거래 생략 | 0 (항상 목표비중으로) |
| 최소 거래금액 (원) | 이보다 작은 매수/매도는 생략 | 0 |
| 리밸런싱 주기 (일) | 마지막 리밸런싱 후 경과일 안내 및 .ics 반복 주기 | 30 |
| 접속 시 팝업 | 접속할 때마다 실시간 시세로 팝업 표시 | 켜짐 |

### 계산 방식
- 총자산 = 예수금 + 추가투입 + Σ(보유수량 × 현재가)
- 종목별 목표수량 = ⌊총자산 × 목표비중 ÷ 현재가⌋, 거래수량 = 목표수량 − 보유수량 (양수 매수 / 음수 매도)
- 매수 대금이 (예수금 + 추가투입 + 매도대금)을 넘으면 예산 안에서 부족분이 큰 종목부터 배분 → 예수금이 음수가 되지 않음
- 수수료/세금은 반영하지 않습니다 (연금계좌 ETF 매매는 대부분 수수료·거래세 없음).

## 구조

```
server/index.js     Express 서버: 정적 파일 + /api/* (시세 프록시, 포트폴리오 저장, 종목검색, 잔고)
server/nhplug.js    NH Plug 클라이언트: 토큰 발급/파일 캐시, 초당 호출 제한, ETF현재가/현재가/계좌목록/잔고
server/master.js    종목마스터(m_new_stock.mst, CP949 고정길이) 다운로드·파싱·검색
server/store.js     data/portfolio.json 저장/검증
public/rebalance.js 계산 로직 (브라우저/Node 공용) — 단위 테스트 대상
public/app.js       프론트엔드
data/               런타임 데이터 (토큰, 포트폴리오, 종목마스터) — git 제외
```

사용 API (NH Plug REST, `POST` + `{"Input_0": …}`)
| 용도 | 엔드포인트 |
|---|---|
| 접근토큰발급 | `/oauth2/token` (운영 전용) |
| ETF 현재가 (+NAV, 괴리율) | `/krstock/quote/v1/etfCurrent` |
| 주식 현재가 (ETF 조회 실패 시 대체) | `/krstock/quote/v1/currentPrice` |
| 계좌 목록 | `/n2/acctinfo` |
| 주식 잔고 (cts 연속조회) | `/krstock/inquiry/v1/balance` |

## 주의
- 서버는 기본적으로 `127.0.0.1` 에만 바인딩됩니다. API 키는 계좌 접근 권한이므로 외부에 노출하지 마세요.
- 이 앱은 **주문을 내지 않습니다.** 제시된 수량을 보고 증권사 앱/HTS에서 직접 매매한 뒤 "거래 완료"로 반영하세요.
- 장 마감 후에는 현재가 = 종가 기준으로 계산됩니다.

## 정적 버전 (GitHub Pages, 서버·API 키 불필요)

`docs/` 폴더에는 Node 서버 없이 동작하는 단일 HTML 버전이 있습니다.

- `docs/index.html` — 모바일 우선 카드형 UI. 설정·보유수량은 브라우저 localStorage 에 저장 (JSON 내보내기/가져오기 지원)
- `docs/prices.json` — ETF/ETN 전 종목 **전일 종가** (NH Plug 종목마스터, 인증 불필요). 우상단에 가격 기준일 표시
- `docs/history/{코드}.json` — 종목별 일별 종가(약 1년). 카드를 누르면 1주/1달/3달/1년 차트로 표시
- **총자산 추이** — 총자산 카드에 최근 1달 미니 차트, 카드를 누르면 1주/1달/3달/1년/전체 차트. 앱에 기록된 거래(신규 투입·리밸런싱)로 날짜별 보유수량·예수금을 되짚어 `예수금 + Σ(보유수량 × 그날 종가)` 를 계산하고, 투입 원금선(기간 시작 평가액 + 순투입)과 비교해 손익을 표시
- `.github/workflows/update-prices.yml` — **매일 08:50 KST** 에 `scripts/build_prices.py`(전일종가) → `scripts/build_history.py`(히스토리에 하루 추가) 실행 후 커밋.
  히스토리가 없는 신규 종목만 네이버 금융 일별 시세로 1년치를 백필하고, 그 외에는 외부 호출 없이 종목마스터 가격을 덧붙입니다.
- 실시간 시세 새로고침, 계좌 잔고 불러오기는 없습니다. (브라우저에서 NH API 직접 호출은 CORS 로 차단되고, 키를 공개 페이지에 넣을 수도 없기 때문)

### 배포 방법
1. GitHub 에 저장소를 만들고 이 폴더를 푸시합니다 (`.env`, `data/` 는 `.gitignore` 로 제외됨).
2. 저장소 **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main` / Folder: `/docs`** 저장.
3. **Settings → Actions → General → Workflow permissions → "Read and write permissions"** 로 설정 (워크플로가 `prices.json` 을 커밋하기 위해 필요).
4. **Actions 탭 → "Update ETF prices" → Run workflow** 로 한 번 수동 실행해 정상 동작을 확인합니다.
5. 페이지 주소: `https://<계정>.github.io/<저장소>/`

### 기준일(가격 날짜) 판정 방식
종목마스터에는 날짜가 없어서 스크립트가 다음 규칙으로 정합니다.
- 가격이 직전 파일과 하나라도 다르면 → 기준일 = 수집일의 **직전 영업일(월~금)**, 파일 갱신
- 가격이 모두 같으면(주말·공휴일·마스터 미갱신) → 기준일과 파일을 그대로 유지
- 공휴일은 달력에 반영하지 않으므로 연휴 직후 하루 정도 어긋날 수 있습니다. `python3 scripts/build_prices.py docs/prices.json --base-date YYYY-MM-DD` 로 강제 지정 가능
- NH 가 마스터를 08:50 이후에 생성하는 날이 있으면 하루 늦은 가격이 들어옵니다. 그런 경우 워크플로의 cron 에 시간을 하나 더 추가하세요 (예: `'0 9 * * *'` = 18:00 KST).
